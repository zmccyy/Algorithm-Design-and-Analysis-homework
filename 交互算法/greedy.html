Greedy / Local choice, global consequence

每一步，
都选眼前最好。然后呢？

贪心算法不回头看。它在每个路口选择当下看起来最优的方向，然后把这个选择当成既定事实。有时它真的能走到全局最优，有时它会被一条闪闪发光的捷径骗进死胡同。

2张通行证
1个交换论证
0次回溯
01

Two permits / 两张通行证

贪心不是“看起来对”

一个贪心算法要通过两道检查：当下这一步能不能安全地选？选完之后，剩下的问题还是不是同一种问题？

01

贪心选择性质

存在一个全局最优解，包含当前看起来最优的那个选择。换句话说：你不需要为了更好的未来，故意放弃眼前这一步。

02

最优子结构

做了这个选择之后，剩余部分仍然是一个同类型的最优子问题。整体最优可以由局部最优 + 剩余最优拼出来。

03

交换论证

证明贪心选择安全的最常用工具：拿一个最优解，把它和贪心的第一个不同选择交换，证明不会变差，再对剩余部分归纳。

02

Interval scheduling / 区间调度

先结束的人，先上车

同一间教室、同一段时间只能安排一个活动。哪种排序策略能选到最多的不重叠区间？切换策略，单步看贪心怎么做决定。

按结束时间从早到晚排序；每次选择与上一个选中区间不重叠的最早结束者。 已选 0 / 最优 4

    交换论证，为什么最早结束是安全的？

    设贪心选的第一个活动是 g（结束最早），某个最优解的第一个活动是 o。因为 g 结束得不晚于 o，把 o 换成 g 不会和最优解后面的活动冲突，也不会减少数量。于是存在一个包含 g 的最优解；对剩下的时间区间继续归纳即可。

    03

    Huffman coding / 合并最小频率

    让最常出现的字符，走最短的路

    每次从优先队列取出频率最小的两棵树，合并成一棵新树。这个看似短视的动作，恰好构造出了最优前缀码。

    Priority queue / 按频率排序

    等待第一次合并。

    每次取两个最小频率；合并后的新节点放回队列。频率相同的节点按名称稳定排序。

    Codebook / 编码表

    合并完成后生成 0/1 编码。

    6 个叶子，优先队列按频率从小到大排列。准备取出两个最小的节点。

    为什么每次合并最小的两个？

    频率最低的两个字符应该待在树的最深处，这样它们的编码最长、贡献的加权路径长度最小。交换论证把“最深的两个兄弟”换成当前最小的两个频率，总成本不会增加。

    04

    When greedy fails / 反例

    看起来最划算，未必凑得出来

    贪心的危险不在于“选错一次”，而在于它没有回头路。两个经典反例，专门用来打醒“按直觉贪”的冲动。

    Counterexample 01 / 找零

    面值 1、3、4，凑 6。

    贪心先拿最大的 4，剩下 2 只能用 1+1；但最优解是 3+3。局部最大面值把后面的选择堵死了。

    411贪心 · 3 枚
    33最优 · 2 枚

    反例已经足够是
    Counterexample 02 / 0-1 背包

    容量 10，物品不可分割。

    按单位价值从高到低拿：C(4,24) → B(5,28) → 剩余 1 格，装不下 A。总价值 52；而 A+C 正好装满，总价值 54。

    C4246.0

    贪心按比例C + B = 52
    最优A + C = 54

    判断口诀

    能证明交换后不变差，才用贪心；只能举出几个“看起来对”的例子，不算证明。 找不到反例也不等于正确，考试里最稳的写法是先写贪心选择，再写交换论证或明确说明反例。

    05

    Proof recipe / 证明配方

    把“直觉”写成可检查的句子

    贪心证明不需要长篇大论，但必须把“替换之后仍然可行、且不更差”说清楚。下面是一个可以直接套用的四步模板。

    A

    先定义选择

    明确贪心每一步到底按什么排序、选什么。把“最早结束”写成可比较的键，而不是模糊的“看起来最好”。

    B

    找第一个分歧

    假设 O 是一个最优解，G 是贪心解。令它们第一次做出不同选择的位置为 i，比较 O 的第 i 个选择和 G 的第 i 个选择。

    C

    交换并检查

    把 O 中的选择换成 G 的选择，证明剩余部分仍然可行，且目标值不变差。注意处理重叠、容量、前缀码等约束。

    EXCHANGE ARGUMENT / 四步模板
    01假设：存在一个最优解 O，它和贪心解 G 在第一个选择处不同。
    02替换：把 O 的这个选择换成 G 的选择。因为 G 的选择是当前约束下最优的，替换通常不会让目标变差。
    03可行性：证明替换后仍满足所有约束（不重叠、不超容量、仍是前缀码……）。这一步最容易被跳过。
    04归纳：替换后的解仍是最优解，且与 G 的第一个选择一致；对剩余子问题重复上述论证，最终得到 G 也是最优解。
    Greedy

    一次决定，
    不再回头。

    • 决策：每一步只选当前最优，不保留其他分支。
    • 正确性：必须证明贪心选择性质 + 最优子结构。
    • 速度：通常是排序 + 一次扫描，O(n log n) 或 O(n)。
    • 典型：区间调度、Huffman、最小生成树、分数背包。
    Dynamic programming

    保留选择，
    比较所有可能。

    • 决策：枚举选择，保存子问题答案，必要时回溯。
    • 正确性：最优子结构 + 重叠子问题，靠状态转移保证。
    • 速度：取决于状态数 × 转移代价，可能更高。
    • 典型：0-1 背包、编辑距离、找零的最少硬币数。
    06

    Self check / 自测

    三道题，检查有没有真的看懂

    先回答，再展开。能说出“为什么”，比记住结论更重要。

    01区间调度为什么按“最早结束”排序，而不是“最早开始”？
    最早结束给后面留下最多时间。 一个活动越早结束，剩余可用区间就越长；最早开始可能选到一个很长的活动，挤掉后面多个短活动。
    02Huffman 每次合并两个最小频率，依据是什么？
    频率越低的字符应该越深。 合并最小的两个会让它们成为兄弟并处在较深位置；交换论证保证把最深处的两个兄弟换成最小频率不会增加加权路径长度。
    03一个贪心算法通过了所有手写样例，可以认为它正确吗？
    不可以。 样例只能说明它在这几个输入上没出错。需要证明贪心选择性质与最优子结构，或者给出反例；找不到反例不等于正确。
    选择证明反例

    贪心算法最迷人的地方，是它把复杂的全局问题压缩成了一次次干净的选择；最危险的地方，也恰好是它不再回头。
