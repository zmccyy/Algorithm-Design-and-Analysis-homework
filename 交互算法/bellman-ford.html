Bellman–Ford / Negative weights

负权，
也能算。

Dijkstra 遇到负权边会失效，Bellman-Ford 却愿意多花一点时间：反复扫描每条边，把距离一点点松弛下去。它还能回答 Dijkstra 无法回答的问题——图里有没有负环？

01

The only move

一条边，怎么松弛？

Bellman-Ford 的全部动作只有一个：如果经过 u 再到 v 更近，就把 d[v] 改小。先把这个动作看透，后面的轮次只是重复它。

Relaxation lab / 单边实验d[u] = 6
ud[u] = 6
w = −4
vd[v] = 9
−4

当前 d[v] = 9。拖动边权，看看 6 + w 是否小于 9。

注意：只有 严格更小 才更新。相等时不更新，这样前驱指针不会被无意义地改写。

d[v] ← min( d[v], d[u] + w(u,v) )

为什么只做这一件事就够了？

一条最短路 A → … → v 的最后一步一定是从某个 u 走边 (u,v) 到达 v。只要 d[u] 已经是到 u 的最短距离，松弛这条边就能把 d[v] 修正到正确答案。

负权边只是让 d 变小

Dijkstra 依赖“取出最小距离后不会再变小”；负权边打破了这个前提。Bellman-Ford 不急着定稿，它给每条边反复翻身的机会。

Relaxation tape / 更新日志

    为什么最多 n−1 轮？

    没有负环时，最短路一定可以选成简单路径，最多经过 n−1 条边。第 k 轮结束时，所有“最多 k 条边”的最短路都已经被确定；所以 n−1 轮足够覆盖全部答案。

    提前停止是优化，不是必需

    如果某一轮扫描没有任何更新，说明已经收敛，可以立刻停止。最坏情况仍然需要 n−1 轮；不要因为提前停止就误以为算法只跑一两轮。

    03

    Negative cycle / 负环

    第 n 轮还能松弛，就出事了

    负环让路径可以无限变短。Bellman-Ford 用一条额外的检查轮发现它；但“发现”之前，先要分清：负环到底从源点能不能走到？

    Detector / 两种说法

    左侧 S 只能到达 A、B；右侧 X→Y→Z→X 的总权重是 −4，是一个负环。

    选择一种检测方式。左侧是普通 Bellman-Ford 的视角，右侧是全局负环检测的视角。

    普通 BF 从 S 出发时，X/Y/Z 的距离始终是 ∞，负环不会造成任何松弛；所以它能返回 S 的最短路，却不知道右边有负环。

    # 全零初值：等价于加一个指向所有点的超级源
    dist = [0] * n
    for _ in range(n):
      changed = False
      for u, v, w in edges:
        if dist[u] + w < dist[v]:
          dist[v] = dist[u] + w
          changed = True
      if not changed:
        break
    else:
      return []   # 第 n 轮仍能更新：全图存在负环

    本题的判分口径

    作业要求：只要图中存在负环，就返回空列表，即使负环和源点不连通。因此只从源点跑一遍 BF 不够；要么用上面的全零初值跑一次检测，要么先单独判断全图负环。

    04

    Why it works / 正确性直觉

    多扫一轮，究竟多知道了什么？

    把“轮”看成路径长度的预算：第 k 轮结束时，所有不超过 k 条边的最短路都已经就位。n−1 轮之后，简单路径的预算用完了。

    01

    最短路是简单路径

    如果没有负环，任何带环的路径都可以把环删掉而不会变长。所以一条最短路最多包含 n−1 条边；这是轮数的来源。

    02

    每轮多推进一条边

    归纳：第 k−1 轮结束后，所有 ≤k−1 条边的最短路已经确定；第 k 轮扫描到那条“最后一条边”时，就会把 ≤k 条边的答案松弛出来。

    03

    第 n 轮还在变

    如果 n−1 轮后仍有一条边可以松弛，说明存在一条更短的、带更多边的路径。它必然重复了某个顶点，于是出现负环。

    第 1 轮≤ 1 条边
    第 2 轮≤ 2 条边
    第 3 轮≤ 3 条边
    ……
    第 n−1 轮≤ n−1 条边
    第 n 轮只用于检查负环

    一句话记住

    n−1 轮负责“算完”，第 n 轮负责“验货”。 提前停止只是发现已经算完，不会改变最坏复杂度 O(VE)。

    05

    Choose your tool / 对比

    Bellman-Ford 不是 Dijkstra 的替代品

    它们解决的是同一类问题，但代价和边界不同。看到负权边，先想到 Bellman-Ford；看到非负权和大图，Dijkstra 通常更快。

    Bellman–Ford

    允许负权，
    还能报负环。

    • 边权：任意实数，可以有负权边。
    • 负环：能检测；第 n 轮仍更新即存在（注意是否要求全局）。
    • 数据结构：只需要边表或邻接表，逐边扫描。
    • 复杂度：O(VE)，适合中小规模或需要负权的图。
    • 典型场景：汇率套利、差分约束、带负权的路径问题。
    Dijkstra

    非负权下，
    更快地“定稿”。

    • 边权：必须非负；出现负权边时正确性没有保证。
    • 负环：不处理，也检测不了。
    • 数据结构：优先队列（堆）；懒删除代替 decreaseKey。
    • 复杂度：O((V+E) log V)，通常比 BF 快一个量级。
    • 典型场景：地图导航、网络路由、非负权最短路。
    易错 01 / 只检测源点可达负环

    标准 BF 从 s 出发只能发现 s 能走到的负环。题目若要求“图中存在负环就返回空”，必须用全零初值或超级源做全局检测。

    易错 02 / 把提前停止当成复杂度

    随机图上可能两三轮就收敛，但最坏情况仍是 n−1 轮；复杂度分析要按最坏情况写 O(VE)。

    易错 03 / 用 INF 直接做加法

    在定长整数语言里，INF + 负权可能溢出成很小的数，制造假更新。先判断 dist[u] 是否可达，或用足够大的哨兵值。

    易错 04 / 不记录前驱

    只存距离可以算出长度，却无法还原路径。松弛成功时同步写 prev[v] = u，最后从终点倒推。

    06

    Self check / 自测

    三道题，检查有没有真的看懂

    先自己回答，再展开。答案不要求背结论，关键是能说清“为什么”。

    016 个顶点、没有负环，最坏需要几轮松弛？
    5 轮。 最短路最多有 n−1 = 5 条边；第 k 轮结束时所有 ≤k 条边的最短路已经确定。第 6 轮只用于负环检查。
    02第 n 轮仍然有一条边可以松弛，说明什么？
    存在负环。 如果没有负环，所有最短路径都能在 n−1 轮内确定；第 n 轮还能变短，说明某条路径重复了顶点并且总权重为负。
    03负环和源点不连通时，普通 Bellman-Ford 会检测到吗？
    不会。 从源点出发时，那些点的距离始终是 ∞，负环不会触发任何松弛。题目要求“全图有负环就返回空”时，要用全零初值/超级源再做一次检测。
    松弛检查收敛

    Bellman-Ford 的温柔之处，是它不要求每一步都做出最终决定。它只是反复问：这条边还能不能更短？
