01

Two basic walks / 两种基本走法

队列向外扩散，栈向深处走

BFS 和 DFS 都会访问每个点、每条边一次。区别只在于：下一个访问谁？这个选择决定了层级、时间戳和能找到的结构。

BFS

一层一层地扩散

用队列保存待访问节点，先发现的先展开。它给出无权图的最短跳数，也天然适合按层处理状态。

典型用途：无权最短路、社交网络几度关系、状态空间最少步数。

DFS

一条路走到黑

用栈（或递归）保存当前路径，发现新节点就继续深入，走不通再回溯。pre/post 时间戳能刻画子树的嵌套关系。

典型用途：连通性、拓扑排序、SCC、环检测、回溯搜索。

03

Topological sort / 拓扑排序

把有向无环图拉成一条线

拓扑序要求每条边都从左边指向右边。DFS 的后序正好给出逆序：最后完成的节点最先被输出。

DAG

先决条件

只有有向无环图才有拓扑序。若 DFS 遇到一条指向当前栈中节点的边，就发现回边，说明有环，拓扑排序失败。

POST

后序倒序

DFS 完成一个节点时记录 post。一个节点完成前，它所有可达的节点都已完成，所以逆后序天然满足边 u→v 中 u 在 v 前。

KAHN

另一种写法

不断取出入度为 0 的节点并删除其出边。若最后处理的节点数小于 V，说明剩下部分有环。两种写法复杂度都是 O(V+E)。

# postorder 在 DFS 完成节点时追加
def dfs(u):
  visited[u] = True
  for v in adj[u]:
    if not visited[v]:
      dfs(v)
  postorder.append(u)

# 逆后序就是拓扑序
topo = reversed(postorder)
04

Strongly connected components / 强连通分量

两遍 DFS，把环缩成点

Kosaraju 的关键不是“找一个环”，而是用反向图记录后序，再按后序递减在原图上划分 DFS 树。每一棵树恰好是一个 SCC。

Pass 01

在 G^R 上 DFS

从每个未访问节点出发，记录完成顺序 postorder。反向图把“谁能到我”变成“我能到谁”。

Pass 02

按后序递减走 G

在原图上按 postorder 从大到小处理节点；每棵 DFS 树就是一个 SCC。先处理“汇”分量，避免串到别的分量。

Condense

缩点得到 DAG

把每个 SCC 缩成一个点，SCC 之间的边形成有向无环图。拓扑序、依赖分析、2-SAT 都从这里开始。

A

为什么反向图？

在 G^R 上后完成的节点，往往位于原图 G 中“没有出边到其他未完成分量”的位置；按这个顺序在 G 上 DFS，就不会越过 SCC 边界。

B

为什么后序倒序？

后序越大，越接近“最后完成”的节点；在 G 中从这些节点出发，DFS 只能走回本 SCC 或已经处理过的分量。

C

缩点之后

同一 SCC 内任意两点互相可达；不同 SCC 之间的边只朝一个方向，否则它们会合并成更大的 SCC。

05

Details / 实现细节

同样叫 DFS，写法差一点结果就差很多

遍历算法的代码很短，但访问顺序、标记时机、递归深度和边的分类都容易出错。下面是最常见的几个坑。

01

什么时候标记 visited？

BFS 在入队时标记，否则同一节点可能被多个前驱重复入队；DFS 在发现时标记。只在出队/完成时标记会破坏复杂度。

02

递归太深怎么办？

链状图可能让递归深度达到 V。Python/C++ 都可能栈溢出；改成显式栈，或在允许时提高递归上限。

03

边分类看什么？

指向未访问点 → 树边；指向栈中祖先 → 回边（有环）；指向已完成点 → 前向/交叉边。DFS 的后序正是由这些信息定义的。

04

遍历所有分量

图不一定连通。DFS/SCC 要在外层循环所有节点，对每个未访问点重新启动一次；只从固定源点跑会漏掉其他分量。

ABDECF

DFS 的 pre/post 像括号：子树的区间完全嵌套在父节点区间内；不相关的子树区间互不相交。这个性质是拓扑排序和 SCC 的共同基础。

06

Self check / 自测

三道题，检查有没有真的看懂

先回答，再展开。重点不是记“用队列还是栈”，而是能解释它为什么导致那个结果。

01为什么 BFS 能求无权图的最短路径？
因为队列按层扩展。 源点距离为 0，先入队的都是距离为 1 的点，再是距离为 2 的点；一个点第一次被发现时，走的就是最少边数。
02DFS 遇到指向栈中节点的边，说明什么？
存在环。 栈中节点是当前 DFS 路径上的祖先；从当前节点能回到祖先，就形成了一条回路。这条边被称为回边，拓扑排序也会因此失败。
03Kosaraju 为什么要在反向图上先跑一遍 DFS？
为了得到正确的分量处理顺序。 反向图上的后序倒序保证第二遍在原图上 DFS 时，不会从一个 SCC 走到另一个还没处理的 SCC。每棵 DFS 树恰好是一个强连通分量。
访问标记回溯

图遍历的本质，是在“还没看过的部分”里做一个选择。队列选择广度，栈选择深度，时间戳选择记住先后，反向图选择重新排列世界。
