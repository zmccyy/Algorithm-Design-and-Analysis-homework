The three moves / 思想

分、治、合，缺一不可

分治不是“把代码拆小”，而是一套可证明的递归结构：切开问题、递归求解、再付出合并的代价。

01 / DIVIDE分

分解DIVIDE

找到一条“切线”，让子问题规模变小、结构不变，并且彼此独立。切口选得好，递归才便宜。

02 / CONQUER治

求解CONQUER

子问题仍然大，就继续递归；小到可以直接回答，就停。base case 是递归的地板，也是正确性的起点。

03 / COMBINE合

合并COMBINE

把子答案拼成原答案。合并常是复杂度的胜负手：扫描、指针、复制，通常记作 f(n)。

适用前提 / 3 conditions

子问题独立（不重叠，否则考虑动态规划） · 结构同构（可递归描述） · 解可合并（合并代价可接受）。三条缺一条，分治就可能只是更复杂的暴力。

Example 01 / 归并排序

把有序拼成有序

最标准的分治样例。对半切、递归排、线性合并；递归树每一层的总代价都是 O(n)，共 log₂ n 层。

How it works

一路切到单元素，
再一层层拼回来。

  • 分按中点对半切开，直到每段只剩一个元素：8 → 4 → 2 → 1。
  • 治单元素天然有序，作为 base case 直接返回，不再递归。
  • 合双指针合并两个有序段，每个元素只被扫描一次，单层代价 O(n)。
Recurrence

T(n) = 2T(n/2) + O(n)
⇒ Θ(n log n)

稳定排序，额外空间 O(n)。在合并分支里顺势统计「右侧先出」的次数，就是逆序对数量。

Example 02 / 最大子数组

三种位置，一个不漏

答案要么完全在左、完全在右，要么跨过中点。前两种递归求解，第三种用两次线性扫描在合并步算出来。

Where can the answer be?

切开之后，
候选只剩三类。

  • 分取中点，切开数组。最大连续子数组只可能全在 左半、全在 右半，或 跨过中点。
  • 治左右两半分别递归求最大值；本演示直接给出递归结果，聚焦最容易被漏掉的合并步骤。
  • 合跨越解 = 以中点结尾的最大左后缀 + 以中点后一格开始的最大右前缀。分别线性扫描。
Recurrence

T(n) = 2T(n/2) + O(n)
⇒ Θ(n log n)

Kadane 算法可以用 DP 做到 O(n)；这道题的分治价值，在于练习“合并跨边界信息”的建模方式。

Example 03 / 棋盘覆盖

把不存在变成存在

8 × 8 棋盘上只有一个特殊格。四等分后，特殊格只落在一个象限；在中心放一块 L 骨牌，给其余三个象限各造一个“假想特殊格”。

Construct the subproblem

没有特殊格，
就造一个给它。

  • 分把 2ᵏ × 2ᵏ 棋盘四等分；唯一的特殊格只属于其中一个象限，另外三个象限暂时“无解”。
  • 治在中心放一块 L 骨牌，正好盖住三个无解象限靠近中心的角格。这三个角格变成“假想特殊格”，四个象限就完全同构了。
  • 合继续递归铺四个子棋盘；骨牌一旦放下就是答案，无需额外合并。
Recurrence

T(k) = 4T(k−1) + Θ(1)
⇒ Θ(4ᵏ) = Θ(n²)

骨牌总数为 (n²−1)/3，同样是 Θ(n²)，因此该铺法在渐进意义下最优。考点是“构造等价子问题”。

伍

Complexity / 主定理

先写递归式，再谈复杂度

分治的复杂度几乎都长成 aT(n/b) + f(n)。把 f(n) 与叶子总成本 n^(log_b a) 比大小，就是主定理的全部直觉。

T(n) = aT(n/b) + f(n)

a ≥ 1 个子问题，每个规模 n/b；f(n) 是分解与合并的代价。比较 f(n) 与临界量 nlogba。

①

叶子压倒合并 · Leaning left

f(n) = O(nlogba − ε)

T(n) = Θ(nlogba)

②

势均力敌 · Balanced

f(n) = Θ(nlogba)

T(n) = Θ(nlogba · log n)

③

合并压倒递归 · Leaning right

f(n) = Ω(nlogba + ε)，且满足正则条件

T(n) = Θ(f(n))

分治 vs 动态规划

子问题彼此独立、不重复计算 → 分治；子问题重叠、需要记忆 → 动态规划。

分治 vs 减治

每次只留下一个子问题，是减治（二分查找）；留下多个，才是分治。
