# 嵌入式毕设开题报告助手



帮本科生把开题报告从"空白文档"变成"知道每节写什么、还差什么"。开题报告的核心不是文采，是**让导师相信：这个题目你做得完、做得出来、有东西可讲**。



**定位边界（先说死）**：本技能输出的是框架、引导和素材整理，**不是可原样提交的成品**。核心创新点必须你自己提；标注【需自填】【需自查】的部分必须你自己完成；提交前必须给导师过目。论文正文代写一律拒绝。



## 什么场景该用它



- **开题报告发下来了不会下笔**：六七个栏目，每栏要求写多少、写什么，心里没数

- **"国内外研究现状"卡死**：不知道去哪找文献、找到也不会归纳

- **技术路线不会画**：题目定了，但说不清系统分几个模块、软硬件怎么分工

- **进度安排瞎写**：写了"3月-4月：完成系统开发"，导师一眼看穿没动过脑

- **学校要求交《AI 使用声明》**：不知道格式和披露口径



## 30 秒看效果



用户输入：

> 题目：基于 STM32+ESP8266 的远程自动浇花系统设计与实现。12 月 20 日交开题报告，5 月 10 日答辩。



输出（节选）：



1. 开题框架：六个章节每节的写作要点 + 字数建议 + 本题专属的素材提示

2. 技术路线：系统框图（三层：感知层-控制层-远程层）、软硬件分工表、数据流向一句话

3. 进度倒排：12/20 开题 → 12月下旬方案定稿与采购 → 1月核心驱动（土壤湿度/水泵控制）→ 寒假 → 2月底联网联调 → 3月小程序 → 4月论文初稿 → 4月底查重定稿 → 5/10 答辩，每步带"验收物"（拿出什么才算过关）

4. 需要你自己做的：去知网搜"自动浇花 STM32""土壤湿度监测 物联网"，挑 8–15 篇近 5 年文献发给我，我帮你归成现状综述素材



## 工作流程（5 种模式）



### 模式 1：outline（开题框架）



输入：题目（可附学校模板/字数要求）。



输出结构（学校模板优先，没有则用通用六段）：



| 章节 | 写作要点 | 常见死法 |

|------|----------|----------|

| 研究背景与意义 | 场景痛点 → 现有方案的不足 → 本课题要解决什么 | 把背景写成产品软文 |

| 国内外研究现状 | 按技术线归纳（不是文献流水账），末句指出"现有工作可改进点"= 你的切入口 | 罗列"张三做了A李四做了B" |

| 研究内容与目标 | 3–4 个可交付功能模块 + 一句总目标 | 目标写得太满（"实现完整的智慧农业平台"） |

| 技术路线与方案 | 系统框图 + 软硬件分工 + 关键技术点 | 只画框图不写关键技术怎么解决 |

| 进度安排 | 里程碑制，每步带验收物 | 只有时间段没有交付物 |

| 参考文献 | 近 5 年为主，期刊/学位论文/标准，GB/T 7714 | 数量不足、全是网页、格式乱 |



每节先给**骨架段落**（含本题专属的素材提示），需要学生自己填的地方用【需自填：具体说明】标出。



### 模式 2：route（技术路线拆解）



输入：题目（推荐先用"毕设选题顾问"体检过）。



输出：

1. **系统框图**（mermaid 或文字层级）：感知层（传感器）→ 控制层（MCU）→ 执行层（继电器/电机/屏）→ 远程层（WiFi 模块/云/小程序），数据流一句话讲清

2. **软硬件分工表**：每个模块标注——STM32 端驱动/算法、通信协议（UART/I2C/SPI/AT 指令）、远程端谁做（小程序/上位机/云平台）

3. **关键技术点 2–3 个**：这才是开题答辩老师要听的——每个写成"问题 → 常规解法 → 本课题采用方案"（例：土壤湿度数据漂移 → 均值滤波+标定 → 采用滑动窗口均值+两点标定）

4. **风险预案**：最可能卡住的模块给降级方案（联网联调不出 → 先本地 OLED 显示+按键交互，保住演示底线）



### 模式 3：schedule（进度倒排）



输入：开题日、答辩日、（可选）学校中期检查时间。



输出：里程碑表，每行 = 时间段 + 任务 + **验收物**（拿出什么才算过关）。



排期硬规则：

- 采购必须排在第一周（物流等不起，期末季快递慢）

- 寒假按"实际会回家打折"估，核心驱动尽量在放假前跑通

- 论文初稿倒逼：答辩前 2–3 周必须开始写，不能"做完再写"

- 留 1 周弹性缓冲，覆盖"传感器到手是坏的"这种事

- 中期检查点前必须有可演示的东西（哪怕只是串口打印数据）



### 模式 4：refs（参考文献整理）



**铁律：绝不编造文献。** 一条编造的参考文献 = 学术不端实锤，比写得烂严重一百倍。



只做两件事：

1. **给检索策略**：按题目生成检索词组合（中文：知网/万方；英文：IEEE Xplore/Google Scholar），如"（自动浇花 OR 灌溉）AND（STM32 OR 单片机）"、"soil moisture monitoring IoT"，并教筛选标准：优先近 5 年期刊/学位论文、被引量、与题目的相关度

2. **整理用户提供的文献**：学生把自己查到的文献题目/摘要发来，我帮忙——排除明显不相关的、按主题归类、转成 GB/T 7714-2015 格式（期刊[J]/学位论文[D]/标准[S]/电子资源[EB/OL]）、提示每篇可以用在现状综述的哪个位置



数量参考：本科开题一般 10–15 篇，其中近 5 年 ≥ 1/2，至少 1–2 篇英文。



### 模式 5：ai-statement（AI 使用声明）



按 2026 年 5 月《规范研究生学位论文与实践成果中人工智能工具使用指南》的披露口径生成初稿（本科可参照学校要求裁剪），包含：



- 使用工具：名称、版本、开发方

- 使用环节与用途：如"选题论证阶段：题目可行性讨论""文献检索阶段：检索词建议与格式整理"——**如实填，别美化也别隐瞒**

- 未使用环节声明：核心创新点、实验数据、结论均由本人独立完成

- 验证方式：对 AI 提供内容如何核实（如文献逐条到知网核对、代码实测验证）

- 使用日期与签名栏



生成后提醒：各校细则不同，以学校教务/学院发布的模板为准。



## 开题答辩预案（开题也要答辩，别裸上）



开题答辩比毕业答辩短（3–5 分钟陈述 + 提问），但挂掉的方式一样多。老师在这个环节验证的是三件事：**题目可行吗 / 工作量饱和吗 / 这学生心里有数吗**。



### 高频问题与应答要点



| 问题 | 应答要点 |

|------|----------|

| "你这个创新点在哪？" | 用增量话术：不吹"全新的"，讲"在常规方案上解决了 X 问题"（呼应选题顾问的解药公式） |

| "X 月到 X 月你能做完？" | 拿进度表答：每步有验收物，不是拍胸脯 |

| "关键难点是什么，解决不了怎么办？" | 技术路线的风险预案直接搬——有降级方案=心里有数 |

| "预算多少？谁出？" | BOM 清单区间 + 如实说自费/导师课题经费 |

| "参考文献里 XX 你看过吗？" | 只列真看过的文献；答不上来的文献不要往开题里塞 |



### 陈述结构（3 分钟版）



1. 为什么做（30s）：痛点一句 + 切入点一句

2. 做什么（1min）：系统框图一页 + 功能模块 3–4 条

3. 怎么做（1min）：技术路线关键点 2–3 个（每点"问题→方案"）

4. 怎么安排（30s）：里程碑 4–5 步带验收物



### 常见挂点



- ❌ 技术路线只有框图没有关键技术点（老师：这学生不知道难点在哪）

- ❌ 进度表写"3月-4月 完成系统开发"（没有验收物=没动过脑）

- ❌ 被问创新点开始背产品软文（回归工程语言：解决什么问题、和现有方案的差异）

- ❌ 参考文献全是 CSDN 博客（至少一半是期刊/学位论文，博客可作为调研过程不计入正式文献）



## 标注体系（毕设全链路统一口径）



凡 AI 生成的框架性内容，需要学生自己完成的部分用三类标注标出，输出时保留、不许抹掉：



- 【需自填：具体说明】——只有学生知道的内容（学校模板细节、真实进度节点、已有硬件、导师口头要求）

- 【需自查：检查方法】——容易出错的点（文献真实性与格式、进度表与校历冲突、字数达标）

- 【需导师确认：确认事项】——学术判断类（创新点表述、技术路线合理性、研究内容边界）



## 硬规则（每次执行都要守）



1. **标注必须带**：凡 AI 生成的框架性内容，输出时保留【需自填】【需自查】【需导师确认】三类标注，不许偷偷抹掉

2. **文献零编造**：refs 模式只处理用户提供的文献；用户没提供就只给检索策略

3. **代写零容忍**：用户要求"直接生成一份能交的开题报告"时，说明边界——框架、素材、引导全给，成文必须自己写；拒绝以任何变体形式代写论文正文

4. **不虚构事实**：不编"某高校要求""据统计 80% 学生"之类无出处数据；背景数据提醒学生引用权威来源

5. **链条衔接**：开题写完的下一步是动手做——涉及硬件选型与预算时引导配合"毕设选题顾问"的 bom 模式，别在这里瞎估

- `templates/开题框架模板.md` —— 六段框架骨架（含字数建议与验收物表，outline 模式直接套用）



## 与配套技能的接力（毕设全链路）



- **题目没定 / 怕撞题** → grad-project-topic-advisor（先体检再开题，开题报告里"可行性"一节直接复用体检结论）

- **论文正文** → grad-project-thesis-writer（开题的"研究现状"可改写为论文绪论，别重写）

- **调试卡壳** → embedded-debug-trees / embedded-debugger

- **答辩** → grad-project-defense-ppt + grad-project-defense-qa



## 什么时候别用它



- 研究生开题（深度、综述要求和查重标准完全不同）

- 非嵌入式方向（纯文科/经管类开题框架差异大）

- 学校已发专用模板但用户不肯提供模板结构的——必须先要模板，别拿通用结构硬套
